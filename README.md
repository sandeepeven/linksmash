# LinkSmash

Save links from any app. Share a link to LinkSmash and it stores the link on the device, adds a title, image and tag for you, and lets you sort links into folders.

- **Offline-first.** Everything is stored on the device with AsyncStorage. There is no backend.
- **Android-first.** Sharing into the app works on Android. On iOS the share extension is turned off for now (see `app.config.js`).
- **Stack:** Expo SDK 54, React Native 0.81 (New Architecture), TypeScript, React Navigation 7.

---

## Quick start

All app work happens in `apps/expo`.

```bash
cd apps/expo
npm install
npm run android      # builds the native app, installs it, and starts Metro
```

After the first build, if you only changed JS or TS, `npm start` is enough. Run `npm run android` again whenever you add a package that has native code.

### Requirements

- Node 18 or newer
- Android Studio with the Android SDK, and `ANDROID_HOME` set
- JDK 17
- macOS with Xcode and CocoaPods, only if you build for iOS

### Environment (optional)

`apps/expo/.env`:

```env
# Fallback metadata provider, used only when parsing the page's HTML finds nothing.
EXPO_PUBLIC_LINKPREVIEW_API_KEY=your_key_from_linkpreview.net
```

The app works without this key; the fallback is simply skipped. Restart Metro after you change `.env`.

## Commands

Run these from `apps/expo`:

| Command                  | What it does                                                |
| ------------------------ | ----------------------------------------------------------- |
| `npm start`              | Start Metro (dev server)                                    |
| `npm run android`        | Build and run on an Android device or emulator              |
| `npm run ios`            | Build and run on the iOS simulator                          |
| `npm run prebuild`       | Regenerate `android/` and `ios/`, then fix the manifest     |
| `npm run prebuild:clean` | Same as above, but deletes the native folders first         |
| `npm run build:prod`     | Local EAS build of an Android release                       |
| `npx tsc --noEmit`       | Type-check the project                                      |

> `android/` and `ios/` are generated by `expo prebuild` and committed. Make native changes in `app.config.js` and then run prebuild. If you edit the native folders directly, the next prebuild overwrites your changes.

## How the code is organised

```
apps/expo/
├── App.tsx              # Entry point: providers, navigation, share-intent handling, Home screen
├── screens/             # One file per screen (Folders, FolderDetail, EditLink, Settings)
├── components/          # Reusable UI (LinkCard, SwipeableLinkRow, LinkEditModal, Toast, ...)
├── services/            # Logic with no UI: parsing, metadata, tags, storage
├── types/               # Data models: LinkData, Folder
├── utils/theme.ts       # Colours, radius scale, useTheme / useThemedStyles
├── scripts/             # fix-manifest.js (runs after prebuild)
└── app.config.js        # Expo config: app id, version, plugins
```

### What happens when a link is shared

```
Another app ──share──▶ expo-share-intent
                         │
App.tsx  extractSharedContent()        pulls text, URL and images out of the intent
                         │
services/linkProcessor   processLinkWithoutAPI()
   ├─ linkParser            extracts the URL and any title/description from the shared text
   ├─ hostnameTagDetection  picks a tag (youtube, amazon, ...), using tagDetection as a fallback
   └─ platformConfig        default image for known platforms
                         │
   "Allow editing before save" setting?
   ├─ on  → LinkEditModal (review, then save)
   └─ off → services/storage.saveLink() + "Link saved" toast
                         │
components/LinkCard      if metadata is missing, fetches it lazily:
   services/metadata  →  htmlParser (Open Graph / meta tags)  →  linkpreview.net fallback
```

### Where to look

| I want to…                         | Go to                                              |
| ---------------------------------- | -------------------------------------------------- |
| Change how links are stored        | `services/storage.ts` (key `linksmash_links`)      |
| Change folders                     | `services/folderStorage.ts` (key `linksmash_folders`) |
| Improve titles, images, descriptions | `services/metadata.ts`, `services/htmlParser.ts` |
| Add or adjust auto-tags            | `services/hostnameTagDetection.ts`, `services/tagDetection.ts` |
| Special-case a site (Flipkart, Blinkit, ...) | `services/linkParser.ts`, `services/platformConfig.ts` |
| Change colours                     | `utils/theme.ts`                                   |
| Add a screen                       | Create it in `screens/`, then register it in `RootStackParamList` and `Stack.Navigator` in `App.tsx` |

### Conventions

- **Styles:** write a `createStyles(theme)` function at module scope and call `useThemedStyles(createStyles)` in the component. Don't hard-code colours; add a token to `Theme` instead.
- **Feedback:** use `useToast().show(message, { actionLabel, onAction })` for messages and undo. Don't use `Alert` for routine feedback.
- **Icons:** use Ionicons from `@expo/vector-icons`, in the outline style when inactive and the filled style when active.
- **Lists:** links render in fixed-height rows (`LINK_ROW_HEIGHT`), so give `FlatList` a `getItemLayout`. Keep scroll-driven state in refs.

## Releasing

1. Bump `version` in `apps/expo/app.config.js`. EAS sets the Android `versionCode` automatically (`autoIncrement` in `eas.json`).
2. Run `npm run build:prod`.

## Troubleshooting

| Problem | Fix |
| ------- | --- |
| Gradle download times out | `expo prebuild` can reset `networkTimeout` in `android/gradle/wrapper/gradle-wrapper.properties`. Set it back to `600000`. If services.gradle.org is slow, download the zip from a mirror, check its SHA-256 against `https://services.gradle.org/distributions/gradle-<ver>-bin.zip.sha256`, and put it in `~/.gradle/wrapper/dists/gradle-<ver>-bin/<hash>/`. |
| Duplicated intent actions in AndroidManifest | `npm run fix:manifest` (prebuild already runs it) |
| Strange Metro or cache errors | `npx expo start -c` |
| Native module not found | Rebuild with `npm run android`. If that fails, try `npm run prebuild:clean` |
| iOS pods are missing | `cd ios && pod install` |
